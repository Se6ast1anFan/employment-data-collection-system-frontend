# 前端 UI 改版提案：调查期工作台

把“我在处理哪一期、现在卡在哪一步、下一步能做什么”放到首屏。企业看单份报表的六步进度，市级看辖区审核队列，省级看分市上报进度。三端共享视觉规范，首页各自突出最常用的工作。

现有截图和代码显示：省级菜单纵向较长，备案、审核、分析和系统入口排在一列；首页将期次、统计、表格和快捷链接集中在同一块白底区域；部分可点击数字与普通统计值只靠浏览器默认链接样式区分；企业已有明确的六步流程，但当前状态和下一步操作还可以更醒目。

## 视觉规范

| 用途 | 颜色 |
| --- | --- |
| 深墨蓝，正文和关键数字 | `#152D43` |
| 雾蓝灰，应用背景 | `#F2F6F8` |
| 白色，表单、表格及内容面板 | `#FFFFFF` |
| 淡青灰，分隔线和行边界 | `#D5E1E7` |
| 滇池蓝，主按钮、链接及当前流程节点 | `#176781` |
| 暖琥珀，待处理和退回提示 | `#875017` |

中文沿用本地可用的微软雅黑与苹方，数字用系统字体的等宽数字特性对齐。页面标题 26–28 px，区块标题 18 px，正文和表格 14 px，辅助说明 13 px。内容左对齐、数量列右对齐，时间与状态尽量完整显示。表格和流程用分隔线组织，只有重要确认弹窗和浮层使用阴影。状态同时用文字和形状表达，错误、作废及发送失败保留清楚的语义提示。键盘焦点可见，动效仅辅助展开与确认，并尊重减少动态效果设置。

## 布局与页面

```text
┌──────────────────────────────────────────────────────────────┐
│ 就业数据采集      当前页面                    组织 / 账号   退出 │
├──────────────┬───────────────────────────────────────────────┤
│ 工作首页      │ 调查期选择      当前期次状态       截止时间     │
│ 业务分组      ├───────────────────────────────────────────────┤
│  …           │ 企业：六步进度 / 退回原因 / 当前可执行的操作    │
│ 分析与报送    │ 市级：待市审 / 市级退回 / 已转报省级           │
│  …           │ 省级：备案与报表待审入口 / 分市进度表          │
└──────────────┴───────────────────────────────────────────────┘
```

线框里的三行代表三个角色各自的首页主区；期次栏仅用于与调查期有关的页面。

- **登录和导航。** 登录页保留完整系统名称与简洁的账号表单，介绍区用“企业填报 → 市级审核 → 省级汇总与分析”说明系统用途。构建方式和开发命令放入文档。导航按各角色已有入口分组，例如省级的“备案与调查期”“审核与进度”“分析与报送”“通知与系统”，当前项用色条、字重和背景共同标记。窄屏用带文字的抽屉菜单；可点击项有清晰的键盘焦点。
- **企业首页。** 让“备案 → 选择调查期 → 保存报表 → 提交报表 → 市级审核 → 省级审核”成为主视觉。退回时按现有规则回到第 4 步，原因紧贴进度，只有后端允许时才提供“修改并重新提交”。窄屏六步纵排。加载失败时保留节点、给出重试，不把未知状态显示成未完成或成功。
- **市级首页。** 待市审与市级退回放在首行，作为进入相应筛选列表的操作；已转报等状态用较安静的数量显示。审核详情统一把本次提交、历史快照和审核时间线分区，保持原有通过和退回权限。
- **省级首页和列表。** 首屏分别呈现备案待审、报表待审，以及各市已上报与未上报明细。企业进度页继续分列“当前备案”和“本期上报”；列表统一采用“筛选 → 结果范围与数量 → 表格 → 分页”，调查期相关统计和备案统计各自注明口径。窄屏优先保留企业名称、状态和操作，其余列可横向滚动。
- **分析和国家上报。** 分析沿用服务端数据和原口径，同组图表保持系列颜色一致，零样本与缺失值分开表示；国家上报按“调查期条件 → 预览与缺报 → 确认冻结 → 模拟回执”组织，明确锁定时机，保留模拟标识和原批次重试规则。

方案复核后，舍弃了用同一排大数字卡片套用三端的布局。企业通常只关心一份报表的当前进度，市级要找需要处理的报表，省级需要比较各市。把视觉重点分别给流程、队列和分市表，也能避免用装饰图占用首屏。

## 实施顺序与验收

1. **先做企业首页样板。** 在现有 Vue 和 Element Plus 工程里统一颜色、字体、页面标题和导航，再改登录页与企业首页；用匿名 Mock 样本核对待备案、草稿、退回、审核中、通过和读取失败等状态。
2. **扩展至市级与省级。** 做两端首页，并统一审核及企业进度列表的筛选、状态、分页和空态；再应用到备案、填报与通知页面。
3. **收尾分析与国家上报。** 统一图例、数字对齐和冻结确认样式；回归桌面与手机、键盘导航、三端入口、筛选分页，以及原有提交、退回、冻结等关键行为。

本提案只涉及界面与交互呈现，保持现有接口、角色权限、状态判定和统计口径。样板用本地匿名数据验证，不写入共享演示库。
