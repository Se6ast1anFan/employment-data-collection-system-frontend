# 第四周成员 B 前端交接记录

日期：2026 年 10 月 30 日。新增与扩展接口严格以 `project/docs/w4-api-contract.openapi.json` 0.4.0 为准；前三周公共功能继续沿用既有契约。

## 已交付功能

- `/city/reports` 和 `/province/reports`：按期次代码、状态筛选和分页；默认本级待审；地区、企业、人数、提交版本和详情。
- 审核详情展示最新已提交表单、全部不可变快照和审核时间线。退回后的未重报草稿不暴露给审核员。
- 通过二次确认；退回备注选填，去空白后发送 null，最多 500 字。通过请求不带备注。
- 审核同时传 expectedVersion 和 submissionVersion，操作期间禁用按钮；409 重读详情和列表，404 关闭详情并提示，字段/网络错误明确反馈。
- 企业显示全部审核状态、最近退回级别/时间/备注。历史可只读查看，并提供退回后的修改重报入口。
- 市级或省级正式退回后可在原窗口关闭后修改重报，仍依赖服务端 canWrite，备案和基准锁定规则不变。保存保留退回状态，重报回到市级待审，快照追加而非覆盖。
- 市、省菜单与角色守卫继续生效；企业无历史导出；省级修订、删除、汇总、报表导出和上报部委本周未开放。

## 状态与权限

| 当前状态 | 执行者与操作 | 下一状态 |
| --- | --- | --- |
| SUBMITTED_CITY | 本市审核员通过 / 退回 | SUBMITTED_PROVINCE / RETURNED_CITY |
| SUBMITTED_PROVINCE | 本省审核员通过 / 退回 | APPROVED_PROVINCE / RETURNED_PROVINCE |
| RETURNED_CITY / RETURNED_PROVINCE | 原企业保存 / 重报 | 原退回状态 / SUBMITTED_CITY |
| APPROVED_PROVINCE | 所有获权角色只读 | 审核完成，不表示汇总或已报部委 |

所有真实范围校验由后端按 Token 组织链执行，越辖区按 404。省级首次市审未通过时不可读取详情；已有市审通过历史的记录可追溯但不允许乱序审核。每次保存、提交、审核均递增 currentVersion；仅提交递增 submissionVersion。

## 验证与边界

自动测试覆盖第三周备案门禁与第四周市退回、省退回、关窗重报、三份快照保留、审核记录追加、旧当前版本/提交版本冲突、外市列表不可见/详情和操作 404，以及省审不可跳过市审。测试共用会话内 Mock，数据不持久化。

类型检查通过；8 个测试文件、21 项用例通过；真实和 Mock 构建成功（既有包体积警告）。浏览器已检查市级菜单、审核列表、状态筛选和空状态；完整审核写入分支由自动化 Mock 测试覆盖，浏览器含数据详情与退回弹窗全流程仍待演示验收。

2026 年 10 月 30 日使用既有市级演示账号只读探测 `GET /city/reports?page=0&size=20` 返回 404，与当前契约“第四周尚未实现或部署”的交付说明一致。本次没有对真实服务器创建账号、期次、报表或审核记录。真实部署后仍需验证两市两条完整流程、跨省权限、共享数据库留痕和浏览器截图。

第二周 D01–D04 正式复验、第三周共享环境页面正式验收仍无测试同学结论；本记录不代替正式复验。V5、MySQL、备份部署由 A/C 负责。

## Mock 操作顺序

运行 `npm run dev:mock`。三个默认演示账号及口令见 README。先完成企业备案并由省级通过，再选开放期次填报提交；退出后市级登录，在辖区报表审核退回，企业修改重报；市级通过后省级退回，企业再次重报并依次经市、省通过。在企业历史和审核详情对照三个提交快照及五条审核事件。

同一浏览器页面内切换账号可共享内存数据，刷新会重置；Mock 默认演示企业属于演示市级机构。跨市拦截由自动测试注入外市角色验证，共享环境两市两企业真实演示待后端准备样例。
